Now Pages

a whimsical guide to existing on the internet

You don't need a brand, you don't need a platform, and you don't need to perform. You just need a small corner of the internet that says: here is where I am, right now.

// section 01

What is a Now Page?

A now page is a single page on your website that answers one simple question: what are you up to right now? Not your whole career history or a curated highlight reel. Just — what's happening in your life at this moment. What you're working on. What you're reading. What's taking up your headspace.

It's the answer you'd give a friend you hadn't seen in a while, if they asked "so what are you into these days?"

Think of it as the anti-LinkedIn... t's not for employers or for followers. It's for the internet version of you — honest, current, and entirely yours.

The now page movement was started by Derek Sivers in 2015. He started putting a /now page on his own site to tell people what he was focused on, and then thought: other people should have these too. So he built a directory. Now there are thousands of them.

✦ What makes it different from...

A blog? A blog is a chronological archive of your past thoughts. A now page is just one snapshot — right now. No scrolling, history, or comments.

Social media? Social media is performative by design to optimize engagement, reactions, and to keep you scrolling. A now page is outside that ecosystem entirely. No algorithm decides who sees it and no one can "like" it. It just exists.

A portfolio? A portfolio says "here's what I've done." A now page says "here's who I am today." Those can overlap, but they're not the same thing.

✦ The community + how to join it

nownownow.com is the directory where people submit their now pages to be listed alongside thousands of others from around the world. It's genuinely one of the nicest corners of the internet — no algorithm, no ads, just people sharing what they're up to.

To get listed: build your page, put it at yoursite.com/now, then submit the URL at nownownow.com/about. That's it. No approval process, no minimum follower count, no hoops.

Browse the directory first. Look at what other people have made. You'll find everything from minimalist text files to fully designed personal pages. That range is the whole point — there's no right way to do this.

Pick Your Fighter

There are a few different ways to build a now page. None of them are wrong. Pick the one that sounds like you — then expand it for your roadmap.

🎨 "I have no idea what I'm doing and that's fine" VIBE CODER ▶

Vibe coding is exactly what it sounds like: you describe what you want in plain English, and AI writes the code. You don't have to understand every line. You're the creative director and AI is the intern who types fast.

This is a completely valid way to build things for your own enjoyment. You'll make decisions about colors, layout, what text goes where, what the vibe is — and AI handles the technical translation. Over time, you'll start to recognize patterns in the code it generates which will help you learn.

What you'll actually do: Open Claude or ChatGPT. Describe your page. Copy the code into a file called index.html. Open it in your browser. Ask for changes. Repeat until it looks right. Then host it. (See Section 6.)

Check out Section 5 (AI Prompting Guide) — it was written specifically for this path.

🔧 "I want to actually learn HTML and CSS" LEARNER ▶

Respect. HTML and CSS are genuinely not that hard for a simple page — and a now page is about as simple as a web page gets. You're looking at maybe a weekend to get comfortable with the basics.

Start here: MDN Web Docs — Learn. It's free, thorough, written by humans, and doesn't try to sell you anything. For a more structured course feel, The Odin Project is excellent and also free.

Realistic time investment: A few hours to get a basic page working. A weekend to get comfortable with layout and styling. You don't need to finish a whole course first — build the page while you learn.

A now page only needs: a heading, a few paragraphs, some basic styling. That's maybe 30 lines of HTML and 50 lines of CSS. You've got this.

Also check out Section 3 (CSS Is An Art Form) — that one's for you.

🚀 "I know HTML/CSS, I just need to ship it" SHIPPER ▶

Skip to Section 6 (Hosting). You know what you're doing.

Pre-deploy checklist:

  • File is named index.html (or now.html if it lives in a subfolder)
  • All image paths are relative, not absolute
  • Fonts load from Google Fonts CDN or are self-hosted — no local file paths
  • Tested in at least one browser and on mobile
  • No localhost references anywhere
  • Have a GitHub account ready (it's free)
GitHub Pages hosts static HTML/CSS/JS for free, forever, with a clean URL. It's the obvious choice for this. The setup takes about 10 minutes.

CSS Is An Art Form (And Nobody Told You)

Here's the thing they don't tell you in most intro coding resources: CSS is a creative medium. It's not just "make text bigger" or "change the color." With CSS alone, you can build glowing buttons, animated gradients, text that glitches on hover, cursor trails, glassmorphism panels, pixel grids, smooth scroll reveals — all without touching a design tool.

This entire page was built with HTML and CSS. The glitter trail following your cursor? CSS animation + a tiny bit of JavaScript. The glowing title that glitches when you hover it? Pure CSS. The dark void background with the drifting dot grid? Two lines of CSS. Tech is art when you decide it is.

Your now page can look like you. Not like a template. Not like a default theme. Like you. The aesthetic kits below are starting points — steal them whole, mix them up, or use them as a reference while you build something entirely your own.

✦ A few CSS things worth knowing exist

Custom properties (CSS variables) — Define your colors once at the top as --my-color: #f7c863 and reuse them everywhere. Change one line, update the whole page.

Gradients — Backgrounds don't have to be flat. linear-gradient, radial-gradient, and layered gradients create depth, glow, and atmosphere with zero images.

Animations & transitions — @keyframes lets you define motion. transition makes hover states smooth. The glitch effect on the title above? That's clip-path + keyframes.

Google Fonts — Free, one line to import, thousands of options. Typography is one of the fastest ways to make a page feel intentional.

Accessibility note: Pretty and readable are not mutually exclusive. Keep text contrast high (light text on dark background, or vice versa — not low-contrast pastels on white). Use relative font sizes (rem, not px). Don't rely on color alone to convey meaning. A great tool: WebAIM Contrast Checker.

Getting Started with VS Code

VS Code is a free code editor made by Microsoft and used by millions of developers. It's not the only option, but it's the one most tutorials will reference, it has the best extension ecosystem, and it's genuinely nice to use even as a beginner.

Download: code.visualstudio.com/download — available for Windows, Mac, and Linux. Free, always.

✦ Extensions worth installing first

Live Server — Right-click your HTML file → "Open with Live Server." Your browser auto-refreshes every time you save. Absolutely essential.

Prettier — Auto-formats your code on save. Keeps things readable without effort.

Color Highlight — Shows a color swatch next to hex codes in your CSS. Small thing, huge quality of life.

Auto Rename Tag — Rename an opening HTML tag and the closing tag updates automatically.

✦ Keyboard shortcuts that will save your life

Ctrl / Cmd + S Save (do this constantly) Ctrl / Cmd + Z Undo Ctrl / Cmd + / Toggle comment on selected line(s) Alt + ↑ / ↓ Move a line up or down Ctrl / Cmd + D Select next occurrence of current word Ctrl / Cmd + Shift + P Command palette — search everything Ctrl / Cmd + ` Open integrated terminal Ctrl / Cmd + B Toggle sidebar

The AI Guide

✦ 5a — Two ways to work with AI

There's no single right way to use AI when building something. But it helps to know which mode you're in before you start, because they lead to different outcomes and different prompts.

🛋️ Backseat Driver — "build it for me, I'll approve" ▶

You describe what you want in as much detail as you can. AI writes the whole thing. You look at it, tell it what to change, and it revises. You never have to understand the code — you just need to know what you like and what you don't.

Good for: getting something working fast, people who hate technical details, when you have a strong visual idea but don't want to learn to execute it yourself.

// example backseat driver prompt
Build me a now page in HTML and CSS. I want a dark background with warm gold text, a pixel-style header font, and soft section dividers. It should have sections for: what I'm working on, what I'm reading, and what's on my mind lately. Keep it simple and easy to edit. No frameworks, just plain HTML and CSS in one file.
// how to ask for edits without breaking things
"The background color feels too dark — can you lighten it slightly and make the section headers teal instead of gold? Don't change anything else."
Pro tip: When something looks wrong, describe what you see, not what you think the fix is. "The text is overlapping the image on mobile" is better than "fix the z-index." Let AI diagnose it.
🤝 Collaborator — "teach me as we go" ▶

You work with AI more like a patient tutor. It writes code, but it also explains what each part does. You ask questions. You try changing things yourself. You use it to understand, not just to execute.

Good for: people who want to actually learn, anyone who wants to be able to maintain their own site, people who enjoy understanding how things work.

// example collaborator prompt
I'm learning HTML and CSS and I want to build a now page. Can you help me build it step by step, explaining what each piece does as we go? Start with just the basic structure — I'll tell you when I'm ready to add styling. I want to understand what I'm building, not just copy-paste it.
// asking a follow-up question
"You used 'rem' for the font size instead of 'px' — what's the difference and why does it matter?"
AI is a genuinely good teacher for this kind of thing because it has infinite patience, zero judgment, and will explain the same concept twelve different ways until one clicks. Use that.

✦ 5b — Let's talk about AI and the environment

If you've spent any time on social media, you've probably seen the discourse. AI is bad for the environment. It steals water. It uses as much electricity as a small country. Some of that is accurate. A lot of it is missing context. Here's the full picture.

~0.3Wh energy per ChatGPT query (text)
~0.3ml water per query for cooling
270ml water per minute on TikTok
0.2 gal water per hour of Netflix

Sources: Connection Technologies 2026, Enlit World, TikTok data center research

A single text query uses roughly the same energy as running a microwave for one second. TikTok, Netflix, Instagram — the things we scroll without thinking — all run on the same data center infrastructure and pull comparable or heavier loads per minute of use. The concern isn't wrong. The framing often is.

The real issue is scale and infrastructure, not your now page session. Training a large model is genuinely energy-intensive — but that happens once and serves millions. The ongoing conversation is about who's building data centers, where, powered by what, and whether those decisions are being made responsibly. That's a policy and corporate governance conversation, not an individual guilt one.

The honest framework: corporations make the infrastructure decisions. Individual users don't get a vote on whether a data center runs on coal or renewables. What you can do is understand the landscape, push for better practices where you have leverage, and make choices that feel right to you — without burning energy on guilt that doesn't move anything.

Some genuinely useful responses: learning to run local models (no cloud queries at all), choosing AI providers that publish transparency reports and use renewable energy, building skills so you need AI as a scaffold less over time. Making lemonade from the lemons we are handed, basically.

A note on learning vs. leaning. AI is a wonderful tool — but you don't become an accountant just because you have a calculator. Learning to build tech and write code is an art form worth preserving. Understanding what you're making, even imperfectly, is different from outsourcing the thinking entirely.

Think of AI as the librarian holding the ancient scrolls. It can find the passage, translate the language, and explain the context — but you still have to decide what you're looking for and what to do with it once you have it. The knowledge belongs to whoever learns it.

✦ 5c — Honest answers to common AI fears

"Is AI going to take my job?"

Some jobs, yes. Specifically: jobs that are primarily about generating high-volume, templated content — certain kinds of data entry, basic image editing, boilerplate writing. For most roles, the more accurate picture is that AI will change what the job looks like, not eliminate it.

The people getting displaced first are the ones who refuse to engage with the tools at all. The people doing well are treating AI like a very fast intern — useful for first drafts and grunt work, still requiring human judgment, domain knowledge, and taste.

Building technical skills (like, say, making a now page) is one of the more durable responses to that uncertainty. Understanding the tools means you're not at their mercy.

"Is it going to become sentient and destroy us all?"

Current AI systems — including the ones you're using to build your now page — are very sophisticated pattern matchers. They don't have goals, desires, or survival instincts. They don't "want" anything. When the session ends, nothing persists. There's no continuous thread of experience building up in the background.

The legitimate long-term concern in this space is about systems designed to pursue goals autonomously at large scale without adequate human oversight — not ChatGPT going rogue while you ask it to change your font size.

Healthy skepticism about AI development is reasonable. Skynet anxiety about the tool helping you build a webpage is not the same conversation.

"Am I cheating by using AI to build my site?"

Cheating at what? Nobody is grading this. A now page is a personal thing you're making for yourself and putting on the internet. The goal is to have a page that represents you — not to demonstrate that you hand-coded every pixel without assistance.

Every developer uses tools. Stack Overflow. Copy-pasted snippets. Libraries someone else wrote. AI is another tool. Using it doesn't disqualify the result.

If you want to learn to write code yourself, AI can be part of that too — as a teacher, not just an answer machine. But if you just want a page that exists and looks good, using AI to get there is completely fine.

"Should I feel guilty every time I open ChatGPT?"

No. See Section 5b for the actual numbers — and then think about the last time you watched two hours of video content without a second thought.

Guilt that doesn't translate into action is just static. If you're genuinely concerned about AI's environmental footprint, the most useful things you can do are: support policy that holds tech companies accountable for their infrastructure choices, prefer providers who publish honest transparency data, and learn skills that reduce your dependency on cloud-based AI over time.

And then, like, go build your page.

Hosting Your Now Page

You've got a file. Now you need it to live on the internet. GitHub Pages is the best option for this — free, permanent, reliable, and it gives you a real URL you can actually submit to nownownow.com.

What you'll end up with: A URL like yourusername.github.io/now — or if you want your own domain, yourname.com/now. Either works.

✦ GitHub Pages walkthrough

  1. Create a GitHub account at github.com if you don't have one. Free. Pick a username you won't regret — it becomes part of your URL.
  2. Create a new repository. Click the + in the top right → New repository. Name it whatever you like (e.g. now). Set it to Public. Check "Add a README file." Click Create.
  3. Upload your file. Click "Add file" → "Upload files." Drag in your index.html (and any images or CSS files if they're separate). Scroll down, click "Commit changes."
  4. Enable GitHub Pages. Go to your repository Settings → Pages (in the left sidebar). Under "Source," select Deploy from a branch, choose main, folder / (root). Click Save.
  5. Wait about 60 seconds. Refresh the Pages settings — your URL will appear. It'll be yourusername.github.io/repositoryname. Click it. Your page is live on the internet.
  6. Update your page anytime by uploading a new version of the file to the same repository. GitHub Pages re-deploys automatically within a minute or two.

✦ Want a custom domain?

If you want yourname.com instead of the GitHub URL, you'll need to buy a domain — Namecheap is a reliable, affordable registrar. Domains are typically $10–15/year. GitHub Pages has documentation on connecting a custom domain once you have one.

Honest advice: Start with the free GitHub URL. Get your page live first. You can always add a custom domain later — it's not going anywhere.

✦ Submitting to nownownow.com

Once your page is live, head to nownownow.com/about and follow the submission instructions. They ask for your name, URL, and location. That's it. You'll be listed in the directory and become part of the movement.

Remember to update your page. A now page that hasn't been touched in two years isn't a now page anymore — it's an artifact. Update it whenever something meaningful changes. Monthly is great. Whenever you feel like it is fine too.
